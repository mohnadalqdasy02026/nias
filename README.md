# NIAS Academy — Website Rebuild

Rebuild of the NIAS Academy (المعهد الوطني للعلوم الإدارية) website.

## Stack

- Backend: Node.js + Express (+ PostgreSQL, node-postgres `pg`)
- Frontend: React + Vite
- Database: PostgreSQL 16 (schema in `database/migrations/`)
- Infra: Docker Compose (`infra/`)

## Structure

```
nias_academy/
├── database/        SQL migrations (001..007) + seed
├── infra/           Docker / nginx / backup
├── docs/            SRS + design docs
├── server/          Express API (workspace)
│   └── src/
│       ├── config/        env loading / DB pool
│       ├── controllers/   HTTP request handlers
│       ├── services/      business logic
│       ├── repositories/  data access
│       ├── models/        schema / row maps
│       ├── routes/        API route definitions
│       ├── middleware/    auth, RBAC, errors, validate
│       ├── validators/    zod schemas
│       ├── utils/         helpers
│       ├── scripts/       migrate, seed
│       ├── app.js         Express app
│       └── server.js      bootstrap
└── web/             React frontend (workspace)
```

## Dev

Requires Node >= 20.

```bash
npm install          # installs all workspaces
npm run dev:server   # API on :3000
npm run dev:web      # Vite on :5173
```

`.env` files: `server/.env` (API) and env vars per `infra/.env.example`.

## Migrations

Run from the `database/` folder (see Step 2 — a Node runner reads
`database/migrations/` in numeric order and records them in
`schema_migrations`).

## Health

`GET /healthz` returns service status (used by Docker HEALTHCHECK).

## Deploy on Render

`render.yaml` describes the `nias-academy` web service (Node, free plan).
It runs migrations on every start and serves the built React app from the
same Express process.

1. Create a Blueprint from this repo in the Render dashboard.
2. When prompted, set `DATABASE_URL` to the Supabase Postgres connection
   string (transaction pooler, port 6543, `?sslmode=no-verify`). The value is
   intentionally **not** committed to the repository.
3. Optionally set `GEMINI_API_KEY` for the AI assistant.
4. `JWT_ACCESS_SECRET` / `JWT_REFRESH_SECRET` are generated by Render.

Free Render services sleep after idle periods; `.github/workflows/keep-alive.yml`
pings `/healthz` every 5 minutes to keep the demo awake.


## Security & rollout notes (current stage)

- **Secrets / database credentials:** A previous Supabase DATABASE_URL was committed in git history (public repo). Rotate the database password/connection string out-of-band in Supabase and update Render environment variables immediately. Never commit .env or credentials; keep all secrets in environment variables only.
- **Production hardening in place:** Helmet, CORS allowlist, API/public rate limiting, login throttling/lockout, and limited public tracking responses (enrollment status lookup returns only non-sensitive enrollment/course/branch/date fields and requires enrollment number + phone). Continue reviewing access controls for admin actions.
- **Phone/SMS features (planned):** Login alerts via phone and SMS tracking links require an external SMS/OTP provider and credentials (not configured). Current MVP uses web-based trainee tracking at /apply?track=trainee#track and /api/v1/public/training/track.
- **Staged rollout:** Academic (student/ministry flow) and training (trainee registration + tracking) paths are separated in navigation and registration. Library/resources, assistant guidance, and content can be expanded incrementally as data is added.
